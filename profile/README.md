## Where we came from

Mistbil is part of a creative software lineage:

**Scratch → TurboWarp → Mistwarp → Bilup → Mistbil**

We're grateful to the teams and communities behind **Scratch**, **TurboWarp**, **Mistwarp**, and **Bilup**. Their work made it possible for us to learn from existing projects and continue building. Please explore each project's repository for its contributors, history, and license details.

## Getting started

1. Open the Mistbil organization and choose the repository you want to work in.
2. Select **Code**, then **Codespaces**, then create a Codespace.
3. Wait for the shared `.devcontainer/devcontainer.json` setup to finish. It uses Node 20, forwards port 8601, and runs `npm ci`.
4. Follow that repository's README for its specific build and run instructions.

## Branching convention

Use this pattern for feature branches:

`features/<feature-name>/<version>`

- Use lowercase kebab-case for the feature name.
- Use semantic version tags such as `v0.1.0`.
- Example: `features/dark-theme/v0.1.0`
- Start each new iteration on a new versioned branch.
- Don't also create a bare `features/<feature-name>` branch; it conflicts with versioned branches under the same path.

## Contributing

1. Start from the repository's current contribution instructions. Create a branch or, where appropriate, a fork.
2. Make a focused change and explain it clearly in your pull request.
3. Ask for at least one review before merging.
4. Keep `main` protected: changes should go through pull requests and review.

Be kind, ask questions, share feedback constructively, and help teammates learn. We're building the project and our skills together.

## Student safety and privacy

We're a school project, so safety comes first. Do not collect student data or create student accounts for Mistbil services without district approval. Follow school and district policies before publishing or deploying anything, and avoid sharing personal information in issues, code, or discussions.
